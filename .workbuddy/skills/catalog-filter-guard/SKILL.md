# 可筛选列表 · 交互守卫（catalog-filter-guard）

## 这个 Skill 解决什么问题

筛选这类交互有个特点：**「做完了」和「做好了」看起来一模一样。**

你点「行星」，屏幕上剩下 8 张卡片 —— 看着是对的。但下面这些毛病**一个都不会报错**：

- 计数还写着「共 11 个」
- 筛到 0 个时屏幕上什么都没有，用户以为页面坏了
- 筛选之后卡片点不动了（重新渲染把事件绑定搞丢了）
- 手机宽度下筛选按钮挤成一团或溢出屏幕

**它们全都不报错。** 所以只能**逐条主动去查**，不能"跑起来没报错就完事"。

这份 Skill 存在的理由，就是把「容易漏、但不会报错」的几条固化下来。

---

## 用它之前先摸清三件事

1. **数据源在哪、总共多少条** —— 本项目是 `src/data/bodies.js`，11 个天体
2. **有哪些维度可以筛** —— 现有类型分布：恒星 1 / 行星 8 / 卫星 1 / 彗星 1
3. **筛选之后要跟着变的有哪些** —— 只改列表？还是计数、空状态提示也要改？

> ⚠️ **一个必须在动手前算清的数**：
> 如果**每种筛选维度下都非空**（本项目正是如此），那就**造不出「无结果」**，
> 验收标准里的第 2 条根本没法验。
> → 这时必须补一个**能产生空集**的维度。本项目选择加一个关键字搜索框，
> 于是「行星 + 搜『月』」就能造出空集。

## 检查清单（6 条）

### ① 三种状态都真实存在

- **怎么查**：真的去点、真的去输入，逐个复现（不是读代码）
- **判据**：三种都能复现，且界面有对应的可见变化
- **不查会怎样**：空分支只写在代码里、实际触发不到 = 白写

### ② 无结果时不能是空白

- **判据**：屏幕上必须**同时**有两样 ——
  ① 一句说明（「没有符合条件的天体」）
  ② 一个出口（「清空筛选」按钮）
- **不查会怎样**：用户看到一片空白，第一反应是"页面坏了"，而不是"没搜到"

### ③ 结果计数跟着变

- **判据**：计数的数字 **===** 当前可见卡片张数（三种状态下都要各验一次）
- **不查会怎样**：筛出 8 个，标题还写「共 11 个」——
  **数字骗人比没有数字更糟**

### ④ 筛选后原有的交互不能坏

- **判据**：**在筛选状态下**点卡片，仍能触发选中（资料卡正常弹出）
- **不查会怎样**：重新渲染最容易丢事件绑定，表现是"点了没反应"

### ⑤ 可访问性

- 筛选按钮必须是 `<button>`（不是 `<div>`），并用 `aria-pressed` 表达选中状态
- 结果数量的变化要能播报出去（`role="status"` 或 `aria-live="polite"`）
- **判据**：键盘 Tab 能走到每一个筛选按钮；读屏能知道"现在剩几张"
- **判据（无结果那一态单独查）**：那个「清空筛选」出口**也必须能用 Tab 走到** ——
  否则键盘用户在"筛出 0 个"里被关住了，出不来，比看不见更严重
- **不查会怎样**：不用鼠标的人根本没法筛

### ⑥ 桌面 + 手机两宽度

- 桌面 1440、手机 390 各跑一遍
- **判据**：横向溢出 0；筛选条在手机上不换行错位、按钮不挤成一条
- **不查会怎样**：桌面好看，手机上错版

## 三种状态怎么**真实触发**出来

| 状态 | 怎么造 | 期望看到 |
|---|---|---|
| **有结果** | 点「行星」 | 8 张卡片；计数「共 8 个」 |
| **无结果** | 保持「行星」+ 搜索框输入「月」 | 0 张卡片；出现说明 + 清空按钮；计数「共 0 个」 |
| **清空恢复** | 点「全部」+ 清空搜索框 | 11 张卡片；计数「共 11 个」 |

> 🔴 **「无结果」这一条最容易只写在代码里、从没被真正点出来过。**
> 必须真的把它点出来，看到那张说明和按钮。

## 本项目落点

| 位置 | 说明 |
|---|---|
| `src/data/bodies.js` | 唯一数据源（11 个天体），不改它 |
| `src/catalog.js` 的 `renderCatalog(bodies)` | **它本来就接受一个数组** —— 所以筛选＝传入过滤后的数组，架构不用动 |
| `src/filter.js`（新增） | 筛选逻辑独立成模块。**不要塞进 `catalog.js`** —— catalog 管"怎么画"，filter 管"画哪些"，是两件事 |
| `#catalog-count` | 结果计数（第 ③ 条要盯的就是它） |
| `#catalog-body[data-state]` | 空态 / 加载态的开关，**复用 Day 8 的机制**（属性 + CSS 决定长相），不要另造一套 |
| `#catalog-list` | 卡片列表本身 |

## 踩过的坑

1. **别拿「代码里写了」当证据。**
   Day 8 做四种页面状态时就是如此：代码写好了，但**能不能真的触发出来是另一回事**
   （最后是用 `Object.defineProperty` 注入空数组、用 `Network.setBlockedURLs` 挡脚本才造出来）。

2. **加了一层 UI 之后，旧的验收脚本会静默失效。**
   筛选条一加，页面变高、元素位置全变 —— 原来那些固定等待的脚本要重跑一遍。
   （Day 11 的教训：给页面加一层结构，等于给所有既有脚本加了一条新前置条件。）

   **第一次调用时踩到的具体形态（务必认出来）**：
   `cdp-catalog` **桌面 3 条红、手机 37/37** —— 一侧过一侧不过。
   真因是脚本用 `getBoundingClientRect()` 拿**视口坐标**直接点、**不先滚动**，
   而筛选条把目录下推 40+px，卡片中心 `y = 932` 落到了视口（高 900）之外。
   ⇒ 点击类脚本**一律先 `scrollIntoView` 再取坐标**；
   并且"改一处会牵动另一处" —— 为点卡片滚下去之后，主图就出视口了，点主图前得 `scrollTo(0, 0)` 滚回去。

3. **手机宽度下的按钮尺寸**：筛选按钮如果做得很小，要按 `ux-guideline #22` 检查
   —— 但注意那条规则的 `Platform` 是 **Mobile**，桌面鼠标不需要 44×44。

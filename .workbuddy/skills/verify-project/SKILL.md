# 发布前检查（verify-project）

## 这个 Skill 解决什么问题

这个项目里有一类 bug，**长得很像"没问题"**：

- 代码改好了，**公网还是旧的** —— 本地怎么点都对，一发链接给别人就穿帮
- 发布副本**过时了**（改代码忘了重新生成副本）—— 本地一切正常，传上去的是上一版
- 密钥**混进了要传上去的那份文件里**
- 云上错误码是 `DATABASE_23505`（带前缀），代码里写的是全等 `=== '23505'`
  —— **本地全绿、线上静默失效**
- `.focus-overlay` 的渐变 alpha 写成 `0.95` —— 详情页文字从底下透出来
- `hidden` **属性设了，但 CSS 的 `display:flex` 把它盖掉了** —— 元素关不掉

**它们全都不报错。** 所以只能**逐条主动去查**。

这个 Skill 就是把这些坑变成一道**能跑的关卡**。

> ⭐ 一句话定位：**它不是"再测一遍功能"，它是"检查交付物本身是不是你要交的那一份"。**

## 怎么跑

### 第 1–10 项（静态 + 接口，不需要浏览器）

在自己的终端里（Windows 上是 Git Bash）：

```bash
cd /d D:\AI部_学习打卡\VibeCoding
bash .workbuddy/skills/verify-project/scripts/verify.sh
```

退出码：全 PASS = `0`；有 FAIL = `1`；只有"未执行" = `0`（但会提醒）。
离线时加 `SKIP_NET=1`，第 6/7/8 项记「未执行」。

### 第 11–13 项（浏览器行为）

**先另开一个终端起本地服务（窗口别关）**：

```bash
cd /d D:\AI部_学习打卡\VibeCoding
python -m http.server 8081 --bind 127.0.0.1
```

> ⚠️ `--bind 127.0.0.1` **不要省**。不加会绑 `0.0.0.0`，
> 同一 Wi-Fi 下别人能通过你的局域网 IP 打开这个网页，看到你电脑上的**文件清单**。

再跑：

```bash
node .workbuddy/skills/verify-project/scripts/verify-ui.mjs
```

默认测 **1440×900 桌面 + 390×844 手机**两档视口。
本地服务没起 / 页面不是我们的页面 ⇒ 记「**未执行**」，**不会**说成通过。

> 💡 也可以直接指向公网：`BASE=https://<静态托管域名>/ node verify-ui.mjs`
> 那种情况下会遇到平台的「风险提醒」中间页，脚本已内置过门逻辑
> （等 2 秒倒计时 + 真实鼠标事件点击）；**不过门就整轮作废**，绝不拿中间页的读数下结论。

### 「全绿」可信吗？—— 用变异测试证明

**全绿有两种可能**：① 东西真的是好的；② **判据是空的**，根本查不出坏东西。
光看"全绿"分不出这两种。所以：

```bash
# 看现在处于哪种状态
bash .workbuddy/skills/verify-project/scripts/mutation-test.sh status

# 一次测一个（别叠加）：
bash .../mutation-test.sh plant-4b      # ①副本夹带文件   → 期望 verify.sh 的 ④b 红
bash .../mutation-test.sh undo
bash .../mutation-test.sh plant-6       # ②改代码不发布   → 期望 ⑤ 绿、⑥ 红
bash .../mutation-test.sh undo
bash .../mutation-test.sh plant-hidden  # ③去掉 [hidden] 兜底 → 期望 ⑫ 红、⑬ 仍绿
#   ⚠️ ③ 有连带：verify.sh 的 ⑤ 也会红（改了一个白名单文件，就躲不过文件检查）
bash .../mutation-test.sh undo          # 撤销 + 回读核对 md5
```

`undo` 会 `cp` 还原并**回读核对 md5**，还会让 `git status` 自证 `src/` 与 `styles/` 干净。
脚本**只做行级增删**（追加整行 / 删整行），不删片段 —— 删片段会产出"语法看着合法"的文件。

### B 组 · 发布一致性

| # | 检查 | 通过标准 | 出处 |
|---|---|---|---|
| ④a | 白名单文件在仓库齐全 | 14 / 14 | Day 20 |

> 🔴 **⑥ 是全脚本最值钱的一条** —— 它抓的是"改了代码没重新发布静态托管"。

> 取文件时带 `?t=<时间戳>` 绕开 CDN 缓存，否则会读到上一版。

> ⭐ **⑤ 和 ⑥ 的关系**：⑤ 过（副本跟得上代码）+ ⑥ 过（公网跟得上副本）⇒ 传递出「公网 = 仓库」。
> 两条分开写，是为了**一眼看出断在哪一环**：⑤ 红 = 忘了生成副本；⑥ 红 = 忘了发布。

| # | 检查 | 通过标准 | 出处 |
|---|---|---|---|
| ⑦ | 跨域白名单 | 放行白名单域名 / **陌生域名不回** / 无 `*` | Day 20 |
| ⑧ | 接口契约 | `ok:true` · `total=11` · items 11 条 · 三个错误分支码对 | Day 17/18 |

> ⚠️ **⑦ 必须带 `Origin` 头去问** —— 不带的话网关什么都不回，

### D 组 · 前端易回归

| # | 检查 | 执行 | 通过标准 | 出处 |
|---|---|---|---|---|
| ⑪ | 遮罩 alpha = 1 | 读 `.focus-overlay` 渲染后渐变里每个颜色的 alpha | **全部 = 1** | Day 24 🔴 |
| ⑫ | `hidden` 真的隐藏 | 逐视图切换后，读每个带 `hidden` 元素的 `getComputedStyle().display` | 全部 `none`（或 `visibility:hidden`） | Day 22 🔴 |
| ⑬ | 控制台 0 报错 | CDP 收集 `Log.entryAdded` / `console.error` / 未捕获异常 | 同源 0 条 | Day 24 |

> 🔴 **⑪ 为什么要读渲染值**：`.focus-overlay` 写在 `background` 简写里，
> 而 `backgroundColor` 对渐变**恒为** `rgba(0,0,0,0)` —— grep 也 grep 不出"实际透出多少"。
> 🔴 **⑫ 为什么要读 `display`**：**`hidden` 属性对 ≠ 视觉隐藏**。
> `.status-form { display: flex }` 是作者样式，**优于** UA 的 `[hidden]{display:none}`。
> Day 22 加 `#edit-form` 时漏了兜底规则 ⇒ 编辑区关不掉，
> 而当时的自动验收查的是 `form.hidden` **属性值**（确实是 `true`）⇒ **全绿**，最后看截图才发现。
> ⭐ 所以 ⑫ 会**逐视图切换**再测：视图容器自己 `display:none` 时，里面元素的 computed display
> 天然是 none，不切视图就查是**假绿**。
> 📌 ⑬ 把"同源错误"和"外部接口失败"**分开算** —— 接口不通是环境问题，不是页面写错了，混在一起会红黄不分。

## 怎么读结果

三态，只有三种：

- **PASS** —— 有实测值支撑
- **FAIL** —— 有实测值证明它不成立
- **未执行** —— 测不了（网络不通 / 服务没起 / 检查本轮为空）。**不算通过，也不算失败**

> 🔴 **不许把"未执行"说成"通过"。** 也不许写"基本完成""应该没问题"。
> 🔴 **「无 FAIL」≠「全做完」。** 汇总那行要把 PASS / FAIL / 未执行三个数**都**念出来。

## 误报和漏报怎么办

这个 Skill 是**活的**——跑出来不顺手就改它，但改之前先分清是哪种：

| 现象 | 该怎么办 |
|---|---|
| **误报**（FAIL 了，但东西其实是对的） | 先问"判据写松了还是写歪了"，改判据；**不要**加 `|| true` 糊过去 |
| **漏报**（该红的地方全绿） | 几乎总是"**判据查的不是真东西**" —— 回到那一条的出处（踩坑记录）重看当初是怎么发现的 |
| 某项**永远红** | 说明判据和现实不符，要么现实该修，要么判据该修。**别让它长期红着**，红了就没人看了 |

**最硬的自检手法：变异测试。** 故意把那个 Bug 放回去（改一处），断言**必须变红** ——
不变红就说明这条断言是**空的**。用上面那个 `mutation-test.sh` 跑，别靠印象。

> ⭐ 本项目已经栽过一次：⑫ 原来只查 `form.hidden` **属性值** ⇒ 属性对、视觉不隐藏，
> 断言**全绿**。改成读 `getComputedStyle().display` 之后才拦得住。

**Day 25 实测的三条变异（全都如愿变红）：**

| 变异 | 期望红 | 实测输出 |
|---|---|---|
| 副本夹带 `planted-extra.md` | ④b | `FAIL ④b 副本里夹带了白名单外的文件：planted-extra.md` |
| 改 `src/catalog.js` 一行但不发布 | ⑥（⑤ 必须仍绿） | `FAIL 公网与副本不一致：13 / 14 一致，以下不同： src/catalog.js` |
| 删掉 `.status-form[hidden]{display:none}` | ⑫（⑬ 必须仍绿） | `FAIL ⑫　status form#edit-form.status-form → display=flex` |

> ⭐ 第二条里 **⑤ 绿而 ⑥ 红**，正好说明红点落在"忘了发布"这一环，不是"忘了生成副本"。
> ⭐ 第三条里 **⑬ 依然是绿的** —— 这个 Bug 一条控制台报错都不产生，
> 这正是它必须靠专门断言（读 computed display）才拦得住的原因。
> ⚠️ 但第三条在 `verify.sh` 那边**会连带红 ⑤**（`副本与仓库不一致：styles/main.css`）——
> 因为变异手段是"改一个白名单文件"，改了文件就躲不过 ⑤/⑥ 的文件一致性检查。
> ⇒ 规律：**改文件类的变异，躲不过文件检查**；所以这一条的"其余仍绿"只对**浏览器三项**成立。

## 踩过的坑

1. **别拿"代码里写了"当证据。** `hidden` 属性写了、`rgba(...,0.95)` 改成 `1` 了 ——
   这些都要**从渲染结果里读回来**才算数。

2. **先修工具，再读数。** 这个 Skill 本身也踩：
   `curl -I <网关>` 读不到 CORS 头（它是 HEAD 且不带 `Origin`）——
   **读数前先确认量具是准的**，否则会把"工具坏了"说成"东西坏了"。

3. **公网探针必须先过门。** 平台的「风险提醒」中间页带 ~1 秒倒计时，
   而且**必须用真实鼠标事件点**（`el.click()` 在它身上完全不生效）。
   不过门就读到中间页的读数 —— 会让你得出一个**完全错误但看起来很硬**的结论。

4. **脚本自定位要自检。** `ROOT` 按脚本位置推，但**推完要验**
   （根目录里得有 `index.html` + `cloudbaserc.json`），否则拷到别处跑会静默扫错目录。
   （Day 23 教训：`ROOT="${BASH_SOURCE[0]%/*}/.."` 这种脚本被拷走就废了。）

5. **加了一层 UI / 换了一个目录，旧脚本会静默失效。**
   本 Skill 加进来之后，`tests/` 和 `.workbuddy/skills/` 都成了"新目录" ——
   ⇒ 必须同步登记进 `TECH_DESIGN.md` §2，否则 ④c 会一直红（**这条红是对的，别去关它**）。

6. **🔴 bash 里没有块注释。** 写 `/* …… */` 时 `/*` 会被当 **glob** 展开成
   `/LICENSE.txt /bin /cmd /dev …`，然后**当命令执行** ——
   报一堆 `command not found`，**而脚本还继续往下跑**，是个**静默的错**。
   （Day 25 写 `mutation-test.sh` 时实测踩到，用 `bash -x` 才定位。）
   ⇒ 已固化成 ③b 这条检查。**这类"工具自己的错"最值得沉淀**，因为下次一定是同一个坑。

7. **判据说"东西是坏的"，先证明判据本身是好的。**
   Day 25 试跑时，14 个文件明明逐字节相同，脚本却报 `0/14 一致` ——
   真因是 `mktemp -d` 在本机返回 `C:\Users\...\Temp/tmp.XXX` 这种**反斜杠混排路径**，
   `md5sum` 于是在输出行首加了转义前缀 `\`，`awk '{print $1}'` 把它一起捞走了。
   另一条：剥注释只挡了"以 `*` 开头"的行，挡不住**块注释的收尾行**，
   差点把一句"用**包含**判"的正确写法当成罪犯。
   ⇒ **先修工具，再读数。**（这是第四次了。）
